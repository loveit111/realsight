# RealSight 答辩与实作评分标准

## 每日 100 分

| 部分 | 分数 | 满分表现 |
|---|---:|---|
| 概念解释 | 20 | 不背定义，能用 RealSight 例子和反例解释 |
| 调用链 | 20 | 说出入口、关键类型、状态变化、输出和失败分支 |
| 设计取舍 | 15 | 说明为何这样设计，并比较至少一个替代方案 |
| 实验与证据 | 20 | 先预测，保留命令/输出，故障只改变一个变量 |
| 测试能力 | 15 | 测试名称清楚，断言行为而非实现细节，可防回归 |
| 边界与诚实性 | 10 | 主动说明未验证内容、安全风险和不能夸大的结论 |

分数解释：

- 90～100：能独立改造并帮助别人排错。
- 80～89：能独立讲清和完成小改动。
- 70～79：基本理解，但遇到跨层问题需要提示。
- 60～69：只记住局部代码，必须补考。
- 60 以下：停止新增内容，重做当天实验和调用链图。

## 答辩追问规则

老师不能只问“是什么”，必须至少追问两层：

```text
第一层：Observation 是什么？
第二层：为什么它不是 Evidence？
第三层：如果直接把 Observation 填入规则，会发生什么错误正结论？
```

学生每个答案应尽量使用“因为……所以……如果不用……那么……”结构。只说“为了安全、
为了解耦、为了性能”不给分；必须指出具体数据、失败模式或生命周期。

## 四个周 Gate

### Week 1 Gate

- 15 分钟画并讲完整数据流。
- 解释八个核心类型和三类 ID。
- 面对一个非法 payload，判断由哪个 validator 拒绝。
- 不看文档完成离线主循环。

### Week 2 Gate

- 10 分钟逐节点讲 LangGraph。
- 从一段 OCR 原文手算 Evidence、Belief 和规则 verdict。
- 写一个 API 错误路径测试。
- 60 分钟内给最小闭环加一个受限 Action。

### Week 3 Gate

- 画线程、队列、停止、关键帧和 gRPC 时序。
- 解释 `drop_oldest`/`block_producer` 的业务选择。
- 给出 `cv::Mat::clone()` 所有权理由。
- 增加一个 C++ 指标或质量 issue，并通过 CTest。

### Week 4 / 简历 Gate

- 真实 OCR、真实摄像头、正式 API 完整演示。
- 30 个样本和可复算报告。
- 缺失/冲突样本错误正结论为 0。
- 展示一个失败样例、修复测试和仍存在的限制。
- 30 分钟连续答辩 + 60 分钟现场小改动。

## 老师判定“熟练”的现场任务

随机抽一个，不允许提前背答案：

1. 给 `Observation` 新增可选 `camera_id`，只做影响分析，不立即改代码。
2. 将队列容量改为 1 并解释统计变化。
3. 让 fake OCR 返回两个矛盾瓦数，定位为何不能形成 confirmed Evidence。
4. 使用错误 interrupt ID 恢复，证明原 interrupt 仍可用。
5. 将 `max_commands` 设为 1，指出 Planner 是否还会被调用。
6. WebSocket 从 sequence 5 重连，说明客户端会收到哪些事件。
7. 给一个 `conditions_met` 结果，列出它没有证明的四件事。

评价重点不是速度本身，而是操作前能预测、操作后能解释、修改时能补测试。
