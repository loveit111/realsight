## 每天的正确学习顺序

不要先看六小时视频，也不要从第一行代码开始逐字翻译。每天按下面顺序：

```text
先预测系统应该怎样运行
→ 学当天必须用到的概念
→ 沿一条调用链读代码
→ 运行一个成功场景
→ 主动制造一个失败场景
→ 写测试固定你的理解
→ 合上资料画图并答辩
```

“先预测”非常重要。只在程序运行后复述输出，很容易产生“我看懂了”的错觉；先写下
预期状态、事件或错误，再运行比较，才能发现自己的心智模型哪里错了。

## 你和老师每天怎样配合

每一天分四次验收，不以“看完文档”作为完成：

1. 开课前把 Day Notes 的三条预测交给老师；老师只纠正会导致错误操作的前提，不提前给答案。
2. 概念和源码阅读后，用五分钟反向讲给老师；老师连续追问“为什么”和“删掉这层会怎样”。
3. 实验后提交命令、预期、实际和最小 diff；老师先检查是否只改变一个变量，再评判结论。
4. 当天结束做闭卷答辩，按评分表打分；低于 70 分必须用新输入重做实验，不能原题背答案。

你可以在后续对话直接说“开始 Day N”，并附上当天的 Day Notes。我会按对应教案先做入门
诊断，再逐题讲解、审查实验和主持答辩。没有真实摄像头/OCR 的日子可以完成代码理解层，
但真实设备 Gate 不会因此自动通过。

## 每天六小时怎样分配

| 时间 | 做什么 | 不合格表现 |
|---:|---|---|
| 60 分钟 | 白话概念和最小例子 | 抄术语定义但不会举例 |
| 90 分钟 | 按课程指定顺序读项目代码 | 从文件第一行漫无目的读到最后 |
| 90 分钟 | 成功实验与故障注入 | 只运行现成 Demo，不改输入 |
| 60 分钟 | 写/改测试 | 先看运行结果再补一个永远通过的断言 |
| 30 分钟 | 画数据流、状态图或时序图 | 只画组件名，没有数据和方向 |
| 30 分钟 | 脱稿答辩和复盘 | 照着 README 念 |

零基础第一周可能需要每天 7～8 小时。可以把一天拆成两天，但不要删除实验和答辩；
“24 天”是内容顺序，不是必须牺牲理解速度的倒计时。

## 学习环境规则

所有命令默认在仓库根目录运行：

```powershell
cd <repo-root>
git status --short
uv run --locked realsight-doctor --config config/realsight.example.toml
```

遵守四条规则：

1. 每次改动前先运行对应测试并记录基线。
2. 每天只改变一个主要变量；例如研究队列容量时，不同时改质量阈值。
3. 不提交 `.env`、密钥、模型缓存、`runtime-data`、构建目录和个人绝对路径。
4. 遇到失败先定位层：环境、契约、传输、OCR、工作流、规则，不能笼统说“Agent 坏了”。

## 贯穿全课的六个问题

读任何文件都问：

1. 它的输入是什么？输入是否已经校验？
2. 它的输出是什么？是事实、请求、状态还是事件？
3. 它拥有哪种副作用：摄像头、网络、磁盘、模型、数据库？
4. 它明确不负责什么？
5. 失败是异常、业务状态、EvidenceGap，还是终态？
6. 进程中断或请求重放后，它会不会重复执行外部副作用？

能够持续用这六问读代码，才算真正开始理解工程，而不是记住文件名。

## 24 天后的熟练标准

“熟练理解”不等于能背代码。你需要做到：

- 给一条 RunEvent 或错误栈，能先判断它属于哪一层。
- 不看图画出 `ObservationRequest → Observation → Evidence → Belief → verdict`。
- 修改一个契约字段时，能列出 Python、Proto、C++、生成代码、测试和兼容性影响。
- 能解释 C++ 背压、停止和关键帧所有权，不把 `cv::Mat` 浅拷贝说成深拷贝。
- 能安全增加一个工作流节点或 provider，并知道什么能进 checkpoint。
- 能给出真实指标及分母，主动展示失败样例，不夸大生产能力。

如果某天的答辩低于 70 分，次日先用 60～90 分钟补考，再进入新内容。
